## 4. Feature Verification & API Usage

- **[✓] PostgreSQL Used:** 
  - `GET /api/v1/crimes/{id}`: Directly queries SQLAlchemy `Crime` model for structured meta-data (Case ID, Priority, Date, etc).
  - `GET /api/v1/crimes/{id}/entities`: Queries mapped records linking suspects, phones, vehicles, and organizations to the case.
  - `GET /api/v1/crimes/{id}/timeline`: Generates an event stream from chronological DB records.
- **[✓] Neo4j Used:**
  - `GET /api/v1/neo4j/high-risk-networks`: Re-used to power the embedded `NetworkGraph.tsx` within the FIR Workspace, drawing subgraphs of criminal associations.
- **[✓] PGVector Used:** 
  - `GET /api/v1/crimes/{id}/similar`: Semantic search over `DocumentChunk` records using the `all-MiniLM-L6-v2` embedding space via `cosine_distance`.
- **[✓] RAG & LLM Used:**
  - `GET /api/v1/crimes/{id}/summary`: Proxies the request through `FallbackManager` to generate real-time AI summaries on M.O. patterns and recommended actions.
- **[✓] Explainability Present:** 
  - `FIRExplainabilityPanel` leverages `ReasoningTracePanel` to expose the exact database records, PGVector vectors, Neo4j graph hops, and confidence levels generated by the AI extraction pipeline.
- **[✓] No Mock Data Check:** 
  - All UI panels utilize React `useEffect` to invoke `/api/v1/crimes/` endpoints dynamically. No static inline mock arrays exist in the frontend layer. If the backend table is empty, an empty state is triggered.
